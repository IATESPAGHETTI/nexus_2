# The 11 minimum requirements: where each one is, how to check it, and what it does not claim

Status words follow the project rule: *implemented + tested*, *verified live* (a real model run was observed), *not verified*.
Every command below is run from the repository root. "Free" means it uses no model and no cloud.

| # | Requirement | Where it lives | How to check it | Limits (say these out loud) |
|---|---|---|---|---|
| 1 | Shared state; different messaging architectures compared; **blackboard** | `orchestrator/blackboard.py`, `agents/common/board_io.py`, board API in `backend/app/incident_store.py`; topologies `hub`, `blackboard`, `pipeline` via `NEXUS_TOPOLOGY` | Free: `pytest agents/tests/test_blackboard_flow.py orchestrator/tests/test_pipeline.py tests/test_blackboard_api.py`. Live: set `NEXUS_TOPOLOGY=pipeline`, Inject; the incident page's *Audit trail* lists every board entry and the Metrics -> hand-off -> other agents order. Measured comparison: `docs/EVALUATION_RESULTS_2026-10-16.md` (hub vs blackboard, DeepSeek, n=18) and the held-out run (see `docs/EVALUATION_RESULTS_HOLDOUT.md`). | Differences between topologies are within noise at these sample sizes. The pipeline needs the Metrics agent in the selection. |

The VM is stopped between uses to save credit. The redeploy/backup/health scripts are written and syntax-checked but not yet run on the VM. Approve -> fix has not been tested on the cloud. |

## What would make a reviewer's claim "fully verified"
Things that are written but have not been observed yet: the Azure scripts running on the VM; Approve -> execute -> verify on the cloud
site; and a sample large enough to separate the multi-agent variants (the held-out run, 126 valid runs on Gemini, measured pipeline, analysis tools and CrewAI Evidence+Critic, but 18 runs per arm cannot rank them; see `docs/EVALUATION_RESULTS_HOLDOUT.md`).
